# Phase 5.1 Entropy Runtime And Path Safety Fix Report

## 1. Summary

Phase 5.1 fixes two runtime blockers seen when testing Efficient Active SLAM utility mode:

- Phase 5 utility mode was not obvious in runtime logs, and local selection still picked by the old heuristic score after utility ranking.
- `path_safety.py` could reject a path by clearance even when the path and nearby cells had zero cost.

The fix keeps the Phase 4.x safety pipeline intact: candidates are still generated by the current safe viewpoint pipeline, then optionally ranked by Efficient Active SLAM utility, then planner-validated before `NavigateToPose`.

No RRT, MPPI, multi-robot communication, or direct goal dispatch bypass was added.

## 2. Root Cause

Efficient utility visibility:

- `active_slam.launch.py` already exposed `enable_efficient_utility` and `scoring_mode`.
- `node_params.py` already declared and read those parameters.
- Runtime logs did not have a dedicated startup line proving Phase 5 mode was enabled.
- `goal_selector.py` called the utility ranker, but then selected `max(candidates, key=candidate.score)`, which could ignore `utility_score`.

Path safety:

- Clearance validation behaved like a binary radius check.
- The diagnostic showed:

```text
max_cost_on_path=0
max_cost_near_path=0
robot_cost=0
goal_cost=0
reason=path_clearance
detail=clearance_radius_hit
```

That should not reject. A zero-cost path with zero near-path cost has no evidence of obstacle, unknown, lethal, or inflated-cost collision in the costmap.

## 7. Path Safety Logic Changes

`path_safety.py` now checks near-path clearance by measured cost:

- Reject if near-path cost is lethal/high:
  - `path_clearance_lethal_cost: 90`
  - `path_clearance_max_near_cost: 70`
- Do not reject low inflation when:
  - `allow_low_inflation_near_path: true`
- Ignore normal start clearance inside:
  - `normal_path_ignore_start_radius_m: 0.25`
- Keep high-cost escape start handling separate:
  - `high_cost_escape_ignore_start_radius_m: 0.35`

`planner_validator.py` now passes those thresholds to `validate_path_safety()`.

## 8. Why Zero-Cost Paths Should Not Reject

If:

```text
max_cost_on_path=0
max_cost_near_path=0
robot_cost=0
goal_cost=0
```

then the checked path samples and surrounding clearance radius are free according to the current costmap. Rejecting that as `clearance_radius_hit` is a false positive and can stall exploration by rejecting every valid path.

The new logic only reports a clearance rejection when the near-path cost exceeds the configured threshold or hits lethal/high cost.

## 9. Marker And Circle Explanation

The visible circle/disk around the robot is usually one of these debug namespaces:

- `blacklist`: failed Nav2 goals, shown with `blacklist_radius_m`.
- `planner_reject_blacklist`: temporary planner reject cache points.
- `selected_goal`: current selected candidate marker.
- `candidate_goals`: sampled candidate viewpoints.
- `planner_rejected_candidates`: candidates rejected by planner/path validation.

These are RViz debug markers only. They do not publish velocity or controller commands.

The README now includes a marker namespace legend.
